# Pre-R1 code review — findings and handoff

**Date:** 2026-08-05 · **Reviewed commit:** `16541f2` (main, clean tree)
**Brief:** software-engineering review of the repo — how clean and correct the Go↔bash
boundary is (design *and* implementation), plus an overall simplification/cleanup pass.
**Method:** multi-agent review (Claude Fable 5) across two sessions. Session 1: 14 scoped
reviewers over the Go engine, the bash payload, the AGENTS.md invariants, and a
simplification pass, plus a 3-lens holistic panel. Session 2 closed the coverage gaps
session 1 recorded as unreviewed: the dedicated Go↔bash boundary review (2 reviewers) and
six gap-closing reviewers (presets, CI/lint policy, embed/v1 audit, docs drift, Go leaf
packages, dogfood config). Every bug/invariant/boundary claim in both sessions was handed
to an independent adversarial verifier instructed to *refute* it.

**Volume:** 153 subagents, ~9.6M tokens. 114 raw findings → **45 confirmed**, 21
downgraded, 30 refuted, 8 judged not-worth-doing, 21 worthwhile improvements.

> **A note on the "invariant" findings.** A large share of what follows is phrased in
> trust-boundary terms. That is not a security audit imposed from outside — it is this

> or evals any byte a container could have written"; "argv only, everywhere"; "no ambient

## 0. Executive summary

### The boundary question — the headline answer

**The Go↔bash split is in the right place, and it is clean enough to ship at R1.** Both
boundary reviewers reached that independently after enumerating 46 and 27 crossing points
respectively (merged inventory in Appendix C — that map is the main deliverable of this
session).

What's genuinely good, and unusual:

- **The stated rule is the implemented rule.** The engine owns every argv, identity env
  var, and rendering of container-controlled bytes; the shell keeps genuinely tmux-shaped
  work — pane lifecycle, click dispatch, `display-menu` mechanics, the poll loop. Layout
  arithmetic, porcelain formats, and verdicts live in Go. There is no raw shell string
  anywhere in the exec paths (one exception, §3's dev builder).
- **The payload re-vets what the engine already vetted.** `agent-open.sh`, `agent-menu.sh`,
  `chooser.sh`, and `sidebar.sh` all charset-gate values a second time before they become
  shell words or tmux targets. Defense in depth that costs nothing.
- **The porcelains are versioned with a documented, correctly implemented one-generation
  skew tolerance** — and the skew case is actually tested (`frame_test.go:1163-1199`),
  `--spin` is flag-gated so an older script keeps its four-line protocol across a binary
  swap, and the legacy verbs are deliberately retained. Most cross-language systems never
  write this contract down at all.
- **The theme pipeline is the exemplar**: one Go source generated into bash, tmux conf, Lua,
  and YAML behind a CI drift gate. Zero drift possible.

Where it leaks, it leaks in a small number of identifiable places:

- **Host-side reads of container-writable git metadata** — the one real breach (§1.1) plus
  an unbounded read that follows a container-chosen path (§3).
- **One missed read cap** (§2.10) — every other container-byte ingest on the host is
  bounded; `agent-ps.sh`'s output is the one that isn't.
- **The `display-menu` layer reintroduces shell-string quoting** (§2.8) that the argv-only
  rule killed everywhere else — a real robustness bug for paths with quotes, not a
  container escape.
- **Four cross-language vocabularies are hand-mirrored** with nothing but dogfooding to
  catch drift (§4.9). This is the single highest-leverage boundary improvement: generate
  them the way `theme.sh` already is.
- **Every bash half of every protocol runs only in production** (§4.5) — the Go halves are
  superbly tested; the shell halves have no execution tests, though `internal/payload`
  already proves the hermetic pattern works.

### Everything else

Mechanical baselines are clean: `gofmt`, `go vet`, `golangci-lint` (0 issues), and the full
`go test ./...` suite all pass. CI additionally runs shellcheck over both payload sides, a
payload-manifest drift gate, and the three-target cross-compile matrix. The documented
host-side smoke test (`init` → `provision` → `config` against a throwaway `HOME`) was run
this session and passes end to end.

Three independent holistic assessors each graded the repo **A-**, converging on the same
reading: an unusually truthful and disciplined codebase whose documentation and import
graph actually agree, held back from an A by (a) load-bearing boundaries enforced by
convention rather than mechanically, (b) `internal/app` accreting three distinct roles, and
(c) test investment inverted at exactly the riskiest edges.

**Four findings are worth fixing before R1:** the trust-boundary breach where the host runs
container-authored programs on the routine TUI refresh cadence (§1.1); a `vibe update` flow
that fails on every second update (§1.2); agent-chosen filenames reaching the terminal
unencoded (§1.3); and a normative doc claim the code contradicts by mounting a writable bind
into the immutable store (§1.4). §5 lists ~21 cleanups worth roughly 200+ deleted lines with
no behavior change.

## 1. Confirmed high-severity findings

### 1.1 Host executes container-authored code via `git` config — trust-boundary breach ✅ verified first-hand
**`internal/app/frame.go:142`** · invariant/**high**

```go
out, err := exec.CommandContext(ctx, "git", "-C", dir, "diff", "--shortstat", "HEAD").Output()
```

`dir` is `rec.Root` — the read-write workspace bind the agent owns. `git` executes
programs named by the repository's own `.git/config`, and **I reproduced this directly**
against git 2.55: setting `core.fsmonitor` to a *relative* path (`./fs.sh`) inside the
workspace caused exactly this command to execute that script. The agent doesn't even need
to know the host path of the workspace.

This violates two AGENTS.md invariants at once: *"The host never executes, sources, or
evals any byte a container could have written"* and *"External processes go through
`runner.Runner`"* (this call resolves `git` from ambient `PATH` and inherits the engine's
entire environment — `cmd.Env` is nil — inside a package whose doc comment promises it
never reads ambient environment).

**Reachability is the aggravating factor: this is not operator-initiated.** Call sites are
`internal/app/fetch.go:87` (`FetchCaches`, driven continuously by the sidebar slow tick
*and* the `_watch` daemon) and `internal/app/tui.go:728` (`RenderFleet`). The boundary
reviewer's independent read sharpens the cadence: under the watch daemon's event
coalescing this fires **as often as every 2s**, not only on the ~30s slow tick, for every
project with a running container, as the operator.

**Fix.** Config-based execution vectors in git are open-ended (`core.fsmonitor`,
`diff.external`, `core.hooksPath`, textconv, …), so hardening flags are a treadmill. The
durable answer is to compute churn **container-side** through the existing payload/exec
channel, where the bytes stay inside the sandbox. If it must stay host-side, route it
through `runner.Runner` with an absolute resolved path, explicit minimal `Env`,
`GIT_CONFIG_NOSYSTEM=1`, `--no-optional-locks`, and `-c core.fsmonitor=false -c
diff.external= -c core.hooksPath=/dev/null` — and accept that the list may grow.

> **Fix this together with §2.12.** `runner.Runner` does not currently enforce the minimal
> environment this fix depends on: a nil `Invocation.Env` silently inherits the engine's
> full ambient environment. Routing git through the runner as-is would move the call
> without closing the env half of the breach.

### 1.2 Re-running `vibe update` for an installed version fails with ErrConflict ✅ verified first-hand
**`internal/release/acquire.go:118`** · bug/**high**

`Acquire` unconditionally writes the artifact record with `InstalledAt: unixUTC(s.now())`
(line 116-118) with **no early-out for an already-installed digest** (verified: lines
55-103 always download, extract, and publish first). `store.writeRecordOnce`
(`internal/store/records.go:58-65`) treats any non-byte-identical rewrite as
`domain.ErrConflict`. A second acquire at a different wall-clock second therefore always
conflicts.

Every sibling writer knows this and reuses the existing record — `app.Provision`
(`releases.go:90-102`, with a comment citing a **2026-08-04 dogfood failure of exactly
this class**), `dev.Sync` (`dev.go:177-197`), `prepareCandidate` (`candidates.go:115-124`).
`Acquire` is the one that missed the pattern.

**The existing test hides it:** `release_test.go:164-168` ("Re-acquire is idempotent")
passes only because the fixture injects a frozen clock, `func() int64 { return 1784000000
}` (`release_test.go:126`). Production wires the real clock (`cmd/vibe/main.go:121`).

**Why this matters now:** `vibe update` is precisely the flow ROADMAP R1 exists to
exercise ("the code paths exist and are tested against fixtures; **they have never seen a
live release**"). This will fire on the second update to any version.

**Fix.** Mirror the Provision pattern: `ReadArtifactRecord` first, return the existing
record on success. Better: centralize as `Store.EnsureArtifactRecord` under the object
lock so four call sites stop hand-rolling it. Add a release test whose injected clock
*advances* between acquires.

### 1.3 Agent-chosen request filenames reach the terminal unencoded ✅ verified first-hand
**`internal/broker/broker.go:112,118,123`** · invariant/**high**

Traced the full chain in-session:
`broker.go:112` builds `fmt.Errorf("%s: %w", e.Name(), err)` from the raw on-disk filename
→ `app/requests.go:59` copies it verbatim via `p.Error()` into `RequestListResult.Problems`
→ `cli/output.go:534` renders it with `fmt.Fprintf(w, "warning: %s\n", p)` — no encoder,
no bounding.

Request files live in the container-writable `.vibe/requests/`, and a POSIX filename may
contain any byte except `/` and NUL, including ESC. AGENTS.md requires agent-authored
strings to reach a terminal *only* through `terminal.Encode`/`terminal.Line`. The request
*content* path is carefully protected (ID charset-gated, reason/summary rune-bounded and
Encoded); the *filename* path is the one unguarded seam. `RequestShow` does it correctly —
compare and copy. The `--json` renderer is safe (`json.Marshal` escapes controls); only the
human/TUI path is exposed, including the TUI's `request list` popup.

**Fix.** Encode each problem string through `terminal.Line` at the app boundary, and keep
the filename structurally separate from engine chrome the way `terminal.Confirmation`
already separates Chrome from Content.

### 1.4 A writable host bind into the immutable snapshot store — and a false normative doc claim ✅ verified first-hand
**`docs/security.md:24` ← `internal/model/compile.go:147-152`** · invariant/**high**

`docs/security.md:24-26` states, in the document whose own authority rule says *"the
engine disagreeing with a claim here is a defect"*:

> The only *writable* host path in the container is the registered project root at
> `/workspace`; the engine's own mounts (payload, broker results) are read-only.

`docs/architecture.md:176-177` repeats it. **The code disagrees.** `schema/types.go:48`
declares `Readonly bool` with no default handling, so an import that omits `readonly:`
(or sets it false) is writable; neither `internal/schema/validate.go` nor
`internal/model/validate.go` rejects it (verified by grep: neither file mentions the
field). `internal/model/compile.go:147-152` then compiles

```go
Source:   path.Join(in.Snapshot.Path, SnapshotImportDir, strconv.Itoa(i)),
ReadOnly: imp.Readonly,
```

— a bind of `~/.vibe/state/snapshots/<digest>/imports/<i>` — and
`internal/dockerapi/containers.go:99-104` passes `ReadOnly` straight to the daemon.

So the container gets a **read-write host bind into the digest-addressed, supposedly
immutable snapshot store**. A write there silently corrupts a store object whose tree digest
no longer matches its content, breaking the AGENTS.md immutability invariant (*"Artifacts,
candidates, and snapshots are addressed by tree digest … and never mutated"*) in addition to
the mount-policy claim. Every later candidate reusing that snapshot digest mounts modified
bytes as "frozen approved input", and GC/doctor digest assumptions are silently violated.
`docs/configuration.md:86-89` half-admits the per-entry mode but never documents that the
omitted-`readonly` default is writable, and its example at line 23 always shows
`readonly: true`.

Worth stressing: this needs no adversary to bite. A project with an rw import and a build
step that writes into it corrupts its own store objects during normal use.

**Fix.** Treat the code as the defect, per security.md's own authority rule. Either reject
`readonly: false` in schema validation until read-write imports have a safe design, or keep
the surface and mount rw imports from an engine-named volume seeded from the snapshot copy —
never from the store path itself. Add a `model.Validate` rule that any `BindMount` whose
source is under the store must be `ReadOnly` except `/workspace`. Then document the default.

### 2.9 PID 1 never reaps orphans — zombies accumulate
**`payload/container/entrypoint.sh:12`** · bug/medium→low, but *verifier could not refute the mechanics*

The dev container's PID 1 execs `sleep infinity`, which never calls `wait()`, and the
engine doesn't set `HostConfig.Init` (`internal/dockerapi/containers.go:113` builds
HostConfig without it). Any process orphaned in the pid namespace re-parents to `sleep`
and becomes a permanent zombie. Two guaranteed vectors in the payload itself:
`lifecycle.sh:36` detaches `agent-plugins.sh` via `(bash ... &)` on every `up`, and every
daemonized inner tmux server (`agent-session.sh`, `svc.sh`) zombifies when its last session
dies. Slow accumulation over a long-lived container. **Fix is one line:** set
`HostConfig.Init = true` (Docker's tini) or give the entrypoint a real reaping PID 1.

## 3. Confirmed low-severity findings

Grouped for triage; each was verified.

**Untrusted text / encoding**
- `internal/terminal/sanitize.go:66` — **`Line` panics on non-positive width** (`slice bounds [:-1]`). `Limits.withDefaults` turns `MaxWidth <= 0` into 120 so `Encode` succeeds, then truncation slices negative. Verified by probe: `Line("two\nlines", 0)` panics. This is the *same bug class already found and fixed for `Diff`* — `DiffLimits.withDefaults` clamps to ≥8 and has a committed fuzz seed (`testdata/fuzz/FuzzDiff/b732342de08c97e4`) — but `Line` got neither the clamp nor a `FuzzLine`. No current caller reaches it. **Fix:** clamp, and add `FuzzLine` beside `FuzzEncode`/`FuzzDiff`.
- `internal/cli/cli.go:114` (also `:95`, `:126`) — **command errors print unencoded and unbounded.** `dockerapi/build.go:121` does `errors.New(msg.Error.Message)` on the daemon's `errorDetail`, which echoes the failing `RUN` instruction from an agent-authored `.vibe/Dockerfile` (`ValidateDockerfile` has no control-character gate); `images.go:117` does the same for registry text. A verifier reproduced raw ESC reaching stderr by test. Downgraded high→medium because the agent must already have gotten a Dockerfile approved.
- `internal/schema/inspect.go:130` — **manifest mapping keys can inject raw newlines into terminal diagnostics.** `checkText` deliberately permits `\n`/`\t` in all scalars *including mapping keys*; key text then flows raw into `FieldError.Path` (`validate.go:111,204-210`) and yaml decode messages (`decode.go:46-52`), reaching stderr unencoded. A verifier reproduced both vectors end-to-end. ANSI is blocked, so impact is *fabricated plain-text engine-output lines*, not escape injection. Downgraded high→medium.
- `internal/dev/dev.go:267` — dev build log tail (`%s`, 30 lines of container-produced compiler output) reaches stderr without `terminal.Encode`. Compare `reconcile.go:298-311`, which bounds *and* encodes the dns sidecar's log bytes correctly.

**Boundary — host reads of container-writable bytes**
- `internal/app/frame.go:98` — **`gitBranch` reads container-writable git files unbounded, and follows a `gitdir:` pointer off-workspace.** `os.ReadFile`s the workspace's `.git` (when a regular file) then `<gitdir>/HEAD` with no size bound, once per session on every `_frame` render (2s cadence per sidebar pane). The `gitdir: ` line is followed verbatim — an absolute path lands anywhere on the host, a relative one can `../` escape — so the host reads `<container-chosen-dir>/HEAD` and renders its first line (through `terminal.Line`, so display is safe). Read-as-data, so not the execution breach §1.1 is; the same function's *stdin* path is deliberately bounded (`maxFrameInput`), so the missing cap is a genuine deviation rather than documented intent. ## 4. Cross-cutting design observations

**From the holistic panel (3 independent assessors, all graded A-) and the boundary panel.**

1. **Every load-bearing boundary is enforced by discipline only.** `.golangci.yml` has no
   depguard/importas rules and CI has no import-graph check. Nothing mechanical prevents a
   future change from importing the Docker SDK outside `dockerapi`, giving `tmuxui` a tmux
   dependency, or letting `schema` learn Docker. The assessor verified via `go list` that
   the documented graph *is* the real graph today — which is exactly why a ~20-line
   `go list`-based test would convert the crown-jewel invariants from prose into failures.
   **Highest leverage-to-effort item in the repo.**

2. **`internal/app` is accreting** (5,359 non-test lines, 18 files, ~25% of the engine).
   Three packages cohabit: the command surface proper, the candidate pipeline, and a
   growing TUI backend. Concrete cohesion smell: `buildExtension`, extension-approval
   markers, and `copyTree` live in `requests.go` but serve `prepareCandidate` in
   `candidates.go`; approval markers are ad-hoc files managed directly by `app` rather than
   a store/registry concern. Also `app/frame.go` vs `tmuxui/frame.go` is a real navigation
   snag.

3. **`model` is no longer a leaf over `schema`.** `CompileInput` imports `registry.Record`,
   `store.Artifact`, and `snapshot.Result` (`compile.go:35-38`), coupling the golden-tested
   plan compiler to three sibling packages' record shapes. A small owned-input struct
   restores the documented spine.

4. **Test investment is inverted at the riskiest edges** (verified, exact numbers):
   `tmuxui` 94.9%, `model` 86.2%, `runtime` 81.1% — but **`internal/dev` 0%** (the package
   implementing the deliberately weakest trust boundary is the least-tested in the tree),
   **`runner` 0%** (the mandated chokepoint for every host subprocess, which §2.11 shows
   contains a live bug the most obvious possible test would have caught), `doctor` 8.8%,
   `dockerapi` 11.2%, `cli` 30.7%, `tmux` 45.0%.

5. **The engine↔payload contract is a distributed cross-language protocol** with **no test
   executing real shell against real porcelain**. This session's boundary reviewers
   sharpened the picture in both directions. The skew machinery is better than session 1
   credited: `frame_test.go:1163-1199` *does* pin the one-generation parse across a binary
   swap, `--spin` is flag-gated so an older script keeps its four-line protocol, and legacy
   `_up`/`_sidebar`/`_fleet`/`_agents` endpoints are deliberately retained. But every *bash*
   half still runs only in production — `sidebar.sh`'s 5-line frame split and click-map
   parse, `state-render.sh`'s title decode, `agent-menu.sh`'s map resolution, the `_open`
   machine-line parse, `reap.sh`'s name gate. Blast radius is bounded (both halves ship in
   one artifact, misrenders self-heal within one slow tick, failures are loud and cosmetic),
   which is why this stays a low-severity test gap rather than a defect — but
   `internal/payload` already executes `popup.sh`, `agent-plugins.sh`, and
   `egress-sample.sh` for real, so the pattern exists and just isn't applied to the
   load-bearing scripts.

6. **`allow-passthrough` + `set-clipboard`** (`payload/host/tmux-tui.conf:94-95`, with the
   container-side twin at `tmux-agent.conf:16`) give a compromised agent an OSC 52
   paste-jacking path into host shells. This may well be a deliberate trade (sixel/image
   support needs passthrough) — but **no doc records it as a decision**, and
   `docs/security.md` is normative. Worth an explicit decision record either way.

7. **Bus factor and comment style.** The dated design-journal comment voice
   ("2026-07-26, Chris; supersedes idle-collapses-to-dot: three dogfood rounds…") is a
   genuine asset for a personal instrument and preserves *why* better than most projects
   manage — but it's a style only its author can sustain, and it raises the effective cost
   of a second contributor. Related: big commits sometimes ship subject-only (the 1500-line
   journaled-transaction commit `06c2c20` has no body), and the poetic subjects are
   grep-hostile when hunting a specific fix. The CHANGELOG compensates — for the author.

8. **Module named `vibe-tui-box`** while the product, binary, and all docs say `vibe`. For a
   project whose thesis is identity and provenance: fix before the first tag, or live with
   it forever.

9. **The cross-language vocabularies want one authority — this is the boundary's single
   highest-leverage improvement.** The theme pipeline proves the pattern works: one Go
   source (`tmuxui/theme.go`) generated by `payload/gen/render.go` into `theme.sh`, tmux
   conf marker regions, nvim Lua, and lazygit YAML, with a CI drift gate. Four vocabularies
   are still hand-mirrored across the language line with nothing but dogfooding to catch
   drift: the agent address grammar (`agents.go:374` ↔ `agent-session.sh:296-315`), the
   cold-kinds list (`chooser.go:166` ↔ `agent-session.sh:305-310`), the name charset
   (`SessionNameRe` ↔ ~8 bash sites), and the click-target grammar (three files, §3).
   Generating them into the payload the way `theme.sh` already is would retire the whole
   class. A cheaper down payment: one skew test that runs the previous artifact's scripts
   against the current binary.

10. **The one place container-controlled bytes are decoded by host bash is the OSC title
    channel** (`agent-state-hook.sh:139-141` → `tmux-tui.conf:519` → `state-render.sh:104-176`),
    with no Go in the loop. A reviewer filed this as a letter-of-the-invariant violation;
    the verifier **refuted** it on the grounds that every layer independently re-sanitizes
    at its own boundary and trusts no upstream copy — `state-render.sh` re-scrubs host-side
    regardless of the container-side scrub, `parseAgentPS` explicitly treats the bytes as
    container-controlled, and `frame.go` re-encodes. It is recorded here because it is
    nonetheless the highest-value target for the payload script tests in §6: it is the one
    place container bytes become tmux option values, and its defense is four hand-rolled
    allowlists outside the fuzz program.

11. **Residency is split across three loops with three self-upgrade mechanisms** (the
    sidebar's 2s loop with exec-on-drift, `spin.sh`'s noclobber lock, and the `_watch`
    flock singleton with shim-drift suicide), each with a written motivation. A reviewer
    proposed consolidating into one `vibe _ui` daemon per server; the verifier **refuted**
    the argument as resting on a symmetry rule the repo never states. Recorded as a shape
    worth knowing about, not a defect: intricate, but every piece is documented and the
    2026-08-04 spinner-healer bug is memorialized in `spin.sh:72-78`.

## 6. Test gaps worth closing before R1

- **`internal/runner` has zero tests** and is the mandated chokepoint for every host
  subprocess — the package §1.1's fix proposes migrating git execution onto. §2.11's
  cancellation bug is the proof of cost: a one-line switch reorder would have been caught by
  the most obvious test the package could have. Everything is hermetically testable with
  `/bin/sh`, `/bin/true`, `/bin/false` and a canceled context — no fakes needed. Minimum:
  relative path → `ErrInvalid`; exit 0/7 mapping; canceled-context → `ErrCanceled` (currently

  when source doesn't compile. The fake supports `WaitCodes`, so it's cheap.
- **`watchStream` (`app/watch.go:166-238`) has no coverage** — three goroutines, two
  `io.Pipe`s, a staleness watchdog, backoff verdicts. The most concurrency-dense code in the
  engine, entirely untested — and CI has no `-race` run to compensate (§3).
- **Request-approve failure orderings** — `TestUpDoesNotApproveOnFailure` pins the
  pointer-moves-last invariant for `Up`, but the equivalent in `RequestDecide`
  (`requests.go:334-351`) has no failing-Up test.
- **Payload script tests** — `agent-ps.sh`, `agent-state-hook.sh`, `agent-session.sh`'s

  `agent-plugins.sh` do. These carry two-implementation contracts pinned only on the Go side.
  `state-render.sh`'s title-vetting allowlist is the single highest-value target: it's the one
  place container-controlled bytes become tmux option values (§4.10), and its defense is four
  hand-rolled allowlists outside the fuzz program.
- **`undoStart` rollback path** (`transaction.go:273`) — the one journal entry kind with no test.
- **Snapshot walker defenses** (`walk.go:124,127-129,155-161`) — hard-link rejection,
  post-open regular-file re-check, and the changed-during-snapshot abort (the package doc's
